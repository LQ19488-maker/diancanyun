# 怎么把队友拉进来一起改（diancanyun）

> 目标：三个人各改各的目录，互不覆盖，谁都不会把演示站搞挂。
> 下面按「你（仓库所有者）」和「队友」两种身份分开写，照着点就行。

---

## 一、你：把队友加成协作者（只需做一次）

1. 打开仓库 `https://github.com/LQ19488-maker/diancanyun`
2. 点右上角 **Settings**（不是仓库页的齿轮图标，是仓库顶部那一排标签里的 Settings）
3. 左侧菜单找 **Collaborators**（新版界面叫 "Collaborators and teams"）
4. 点绿色按钮 **Add people**
5. 输入队友的 **GitHub 用户名、全名或邮箱**（他注册 GitHub 用的那个邮箱最稳）→ 选中 → 权限选 **Write**
6. 点 **Add … to this repository**

权限怎么选：

| 权限 | 他能做什么 | 建议 |
|---|---|---|
| Read | 只能看、只能 clone | 不用 |
| **Write** | 能推分支、能开 PR、能评论 | **选这个** |
| Maintain / Admin | 能改仓库设置、能删仓库 | 不要给 |

### 怎么确认他加进来了

- 同一个页面的 **Manage access** 列表里能看到他的头像，状态是 `Pending invite`（等他接受）
- 你想看他到底接受了没有：打开 `https://github.com/LQ19488-maker/diancanyun/invitations`，这里能看到所有还没接受的邀请；列表空了就是都接受了

### 队友那边要做的（你把下面这段发给他）

1. 打开邮箱，找标题类似 **"[LQ19488-maker/diancanyun] Invitation to collaborate"** 的邮件
2. 点邮件里的 **View invitation** → 在打开的页面点 **Accept invitation**
   （收不到邮件就直接打开 `https://github.com/LQ19488-maker/diancanyun/invitations` 点接受）
3. 接受成功后，这个仓库就会出现在他自己的仓库列表里，可以直接 `git clone` 并 `git push` 分支了

## 二、每个人本地怎么拉、怎么改、怎么提交

第一次（只做一次）：

```bash
git clone https://github.com/LQ19488-maker/diancanyun.git
cd diancanyun
```

以后每次干活：

```bash
git checkout main
git pull origin main              # 先拿到最新代码
git checkout -b backend/order-api # 新建自己的分支（名字见下表）
# ……改代码……
git add -A
git commit -m "feat(order): 订单分页接口"
git push -u origin backend/order-api
```

分支名统一一下，谁的分支一眼能看出来：

| 谁 | 分支名前缀 | 例子 |
|---|---|---|
| 你（前端） | `front/` | `front/h5-address` |
| 后端同学 | `backend/` | `backend/order-api` |
| 另一位 | `docs/` 或 `fix/` | `fix/login-401` |

**不要直接往 `main` 推。** 想彻底防住的话，你可以在
`Settings → Branches → Add branch protection rule`，分支填 `main`，
勾上 **Require a pull request before merging**，这样谁都只能走 PR 合并。

## 三、谁改哪块（避免冲突的硬规矩）

| 目录 | 谁改 | 说明 |
|---|---|---|
| `frontend/` | 你（LTQ） | 别人别动，Vue 代码改动很容易互相覆盖 |
| `backend/` | 后端同学 | 你也不动；Java 依赖、`pom.xml` 都在里面 |
| `docs/` | 谁改接口谁改文档 | 改接口的同学顺手更新 `api-contract.md` |
| `.github/workflows/` | 只有你 | 它一改就会影响自动发布，别让别人误碰 |
| 根目录 `README.md`、`.gitignore` | 你 | 别人要改先在群里说一声 |

另外三条：

- `node_modules/`、`dist/`、`target/`、`*.log`、本地数据库文件 **一律不提交**（`.gitignore` 已经写好了）
- 前端改完推上去，**大约 1 分钟后**演示站自动更新（只构建 `frontend/`，见 `.github/workflows/deploy.yml`）
- 只改 `backend/**` 的提交不会触发发布，所以后端同学随便推，不会影响演示站

## 四、代码怎么合到一起：走 Pull Request

1. 队友推完分支后，打开仓库 → **Pull requests** → **New pull request**
2. 左边选 `main`，右边选他的分支 → **Create pull request**
3. 你在 PR 页面里点 **Files changed** 看一眼改动（红色删除、绿色新增）
4. 没问题点 **Merge pull request** → **Confirm merge**
5. 合并完提醒他本地更新：

```bash
git checkout main
git pull origin main
git branch -d backend/order-api   # 删掉已经合掉的分支
```

合并方式二选一，**定一个就别换**，否则提交历史会很难看：

- **Squash and merge**：一个 PR 压成一个提交（推荐，历史干净）
- **Merge commit**：保留每个提交（想看清每一步用这个）

### 遇到冲突怎么办

CONFLICT 的意思是：同一个文件的同一行，你俩都改了。

```bash
git checkout main
git pull origin main
git checkout backend/order-api
git merge main          # 这里会提示哪些文件冲突
# 打开冲突文件，找 <<<<<<< ======= >>>>>>> 三段，
# 留下要的内容，把这三行标记删掉
git add -A
git commit -m "merge main into backend/order-api"
git push
```

规则：**谁的分支谁解决冲突**，别让别人替你改你的代码。

## 五、后端同学原来那个仓库怎么办

他现在的东西在 `TianCha101/dandanyun`。两条路：

- **推荐：以后就在 `diancanyun/backend/` 里开发**。他那边的代码拷过来（或直接把整个目录拖进来）提交一次，之后统一在 `diancanyun` 里推分支。
  好处是三个人只有一处代码、一个 Issues 列表，答辩演示也只需一个链接。
- 想保留原来的提交历史：用 `git subtree` 把那边并进 `backend/`（会多出一堆历史提交）。
  这个方法容易出错，要合的时候叫我一起做。

不管走哪条，**都要先把你邀请他协作者这件事做完**，否则他 push 会报 403。

## 六、人多起来之后的两种替代方案（现在不用，知道有就行）

- **Fork + PR**：不给 Write 权限，让他 fork 你的仓库改自己的副本，再提 PR 给你合。适合不太熟的人，缺点是每次都要同步上游。
- **建 Organization**：把仓库转到 GitHub 组织下（比如 `diancanyun-team`），队友按 Team 授权，人多时管理更省事，仓库网址会变。

---

## 七、一句话总结

你：加 Collaborator（Write）→ 对方接受邀请 → 各自拉 `main` 开分支 → 推分支 → 开 PR → 你合并。
目录各管一块，`main` 只走 PR，`frontend/` 只你改，`backend/` 只他改，冲突谁的分支谁解决。
