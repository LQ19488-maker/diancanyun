# 本次前后端桥接改动说明

## 背景

远程 `main` 已从「管理员 / 员工」点餐版本升级为：

- 商家 `MERCHANT`
- 骑手 `RIDER`
- 顾客 `CUSTOMER`

旧的桥接实现基于 `ADMIN / STAFF` 和堂食桌号，不能直接合并到新版本。本次改动把后端和前端接入层同步到最新三角色外卖流程。

## 主要改动

### 1. 认证契约

- 统一登录入口改为 `POST /auth/login`
- 新增 `GET /auth/me`
- 保留旧登录路径兼容，但新前端只使用 `/auth/**`
- JWT 角色改为 `MERCHANT / RIDER / CUSTOMER`
- `/admin/**`、`/rider/**`、`/user/**` 分别校验对应角色

### 2. 员工模块改为骑手模块

- 删除旧的员工管理接口和前端耦合
- 新增 `/admin/rider/**`
- 支持骑手账号、编号、站点、车型、启停、上线/休息
- 骑手有在途订单时禁止删除
- 停用账号时自动下线

### 3. 新增骑手端后端

- `GET /rider/me`
- `GET /rider/stats`
- `PUT /rider/online`
- `GET /rider/tasks`
- `POST /rider/tasks/{orderId}/grab`
- `GET /rider/orders`
- `POST /rider/orders/{orderId}/finish`

### 4. 外卖订单流程

订单状态保持四段式：

```text
PENDING -> ACCEPTED -> DELIVERING -> DONE
```

- 商家只负责接单或取消
- 骑手抢单后进入配送中
- 骑手确认送达后进入已完成
- 订单保存店铺、收货地址、配送费和骑手快照

### 5. 店铺和收货地址

- 新增 `/user/shops`
- 新增 `/user/shop/{id}`
- 菜单支持 `shopId`
- 新增收货地址增删改查和默认地址接口
- 下单时校验店铺营业状态、起送价和地址归属

### 6. 前端桥接修复

#### Vite 代理

代理前缀从旧的：

```text
/admin /user /upload /api
```

补充为：

```text
/auth /admin /rider /user /upload /api
```

否则新登录和骑手接口会被 Vite 返回 404。

#### 旧会话兼容

浏览器中如果残留旧版 `ADMIN / STAFF` token，新路由守卫会不断把 `/login` 重定向到自身并白屏。现在检测到角色无法映射首页时会主动清理旧会话并停留在登录页。

### 7. 文档

- 更新根 README 的后端状态
- 更新接口契约为三角色与外卖流程
- 新增后端接口兼容清单
- 补充本次改动说明

### 8. 跟进远程最新外卖功能

合并远程后续提交后，又补齐了两部分：

- 骑手的 `todayDone`、`onTheWay`、`doneCount` 和收入全部按真实订单统计，不再依赖骑手表中的缓存值
- 店铺和菜品、套餐增加 `shop_id` 维度；`/user/menu?shopId=` 可返回不同店铺的独立菜单
- 商家后台默认使用 `MERCHANT_SHOP_ID=10001`，不会混入其他店铺菜品
- 当前演示数据包含两家可点单店铺，以及菜单接入中和休息中状态的其他店铺

## 已知边界

- GitHub Pages 演示站继续固定使用 Mock，不会自动连接本地后端
- 真实后端联调需在 `frontend/.env.local` 中关闭 Mock，并设置代理地址
- 生产部署仍需配置正式数据库、JWT 密钥和 Nginx 代理

## 后端接手修复（2026-11-13，桂誉）

在 `backend/platform-compat` 分支上按接口契约逐项补齐，共四组改动：

### 1. 时间格式

`config/JacksonConfig` 统一注册 `LocalDateTime / LocalDate / LocalTime` 序列化器：
`yyyy-MM-dd HH:mm:ss`、`yyyy-MM-dd`、`HH:mm:ss`。此前是 Jackson 3 默认的
`2026-11-13T19:23:43`，与契约不符。

### 2. 计数与分页恢复成数字

根因是 Jackson 把 `Long.TYPE`（基本类型 `long`）也当主键注册成了字符串序列化器。
现在规则固定为：**主键 `Long` → 字符串；计数/分页 `int` → 数字；金额 `BigDecimal` → 数字**。
涉及 `CategoryService`、`OrderService`、`StatisticsService`、`RiderService`。

### 3. 满减

- `shop` 表新增 `full_amount`、`reduce_amount`；`orders` 表新增 `discount`
- 下单按「菜品小计 → 满减 → 打包费 → 配送费」计算：
  `totalAmount = amount - discount + packFee + deliveryFee`，减免额不会超过菜品小计
- 订单出参（下单/详情/列表）新增 `discount`；店铺与菜单出参新增 `fullAmount`、`reduceAmount`
- 种子数据：川味小馆满 30 减 5、稻香快餐满 20 减 3、轻食研究所无、夜宵炸物局满 40 减 8

### 4. 商家端店铺设置接口

- `GET /admin/shop`、`PUT /admin/shop`（详见 `api-contract.md` 3.7 节）
- 店铺固定为配置项 `app.merchant-shop-id`（默认 `10001`），与菜品、套餐的过滤店铺一致
- 校验：满减额不能大于门槛、门槛为 0 不得设优惠额、金额非负、`status/openMenu` 只能 0/1

### 数据库升级提醒

`schema.sql` 使用 `CREATE TABLE IF NOT EXISTS`，**已存在的库不会自动加列**。
老库（如 `diancanyun`）直接启动会报 `Unknown column 'full_amount'`，需要重建库或执行：

```sql
ALTER TABLE shop ADD COLUMN full_amount DECIMAL(10,2) NOT NULL DEFAULT 0,
                 ADD COLUMN reduce_amount DECIMAL(10,2) NOT NULL DEFAULT 0;
ALTER TABLE orders ADD COLUMN discount DECIMAL(10,2) NOT NULL DEFAULT 0;
```
