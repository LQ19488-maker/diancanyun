## 二、每页的验收标准

### 1. 登录 `/#/login` ✅

- [x] 失败 toast 后端 `msg`
- [x] 演示模式预填第一个演示账号，并在提示条里列出全部演示账号（`merchant` 商家、`rider`/`rider2` 骑手、`customer` 顾客），**点一下直接填入**

## 三、全站通用验收项（每页都要过）

| 检查项 | 标准 |
|---|---|
| 三态 | 加载骨架屏 / 空数据一句人话 + 操作入口 / 出错显示错误码 + 重试 |
| 分层 | 页面里无 axios、无接口 URL、无字段名转换、无魔法状态值 |
| 权限 | 无权限路由被守卫拦下；菜单按角色隐藏 |
| 操作反馈 | 成功 toast、失败 toast 用后端 `msg`、危险操作二次确认 |
| 分页 | 页码 / 每页条数 / 总数正确；末页删空回退 |
| 体积 | `npm run build` 产物 ≤ 2 MB（当前 0.74 MB） |
| 刷新 | 任一页面刷新后不回登录页、不白屏 |

## 四、答辩演示动线（3 分钟）

1. **商家登录**（`merchant / merchant1234`）→ 侧栏 6 个菜单，右上角显示姓名
2. **工作台** → 4 张指标卡（口径：只统计未取消的订单）+ 3 张图表
3. **订单管理** → 待接单 → 接单 → 打开详情看状态时间轴与收货地址
4. **骑手管理** → 搜索“胡” → 新增骑手 → 把某一行切成「休息中」（开关 + toast）
5. **菜品管理** → 搜“宫保”→ 上下架切换
6. **骑手端**：登录 `rider / rider1234` → 接单大厅点「抢单」→ 我的配送 → 确认送达
7. **顾客端**：登录 `customer / customer1234` → 选店铺 → 点两个菜 → 购物车（看起送价）→ 选地址 → 提交 → 订单详情看到骑手姓名和电话
8. 讲一句工程话术：「接口层做了双数据源，演示版走内置数据；后端就绪后只改一个环境变量就能切真接口」
