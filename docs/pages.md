## 二、每页的验收标准

### 1. 登录 `/#/login` ✅

- [x] 账号 / 密码校验（必填、长度）
- [x] 回车提交、按钮 loading
- [x] 成功后写 token + 资料到 localStorage，跳 `redirect` 或 `/dashboard`
- [x] 失败 toast 后端 `msg`
- [x] 演示模式预填 `admin / admin1234` 并显示提示条
- [x] 已登录访问 `/login` 自动跳工作台
- [ ] 验证码（不做）

### 2. 工作台 `/#/dashboard`

- [x] 4 张指标卡：今日营业额 / 今日订单量 / 客单价 / 完成率

- [ ] 订单状态分布环形图
- [ ] 热销菜品 Top10 条形图
- [ ] 每张图带口径说明与导出 PNG

- [x] 表单校验：账号格式、密码 8–64 位、手机号、姓名必填

## 三、全站通用验收项（每页都要过）

| 检查项 | 标准 |
|---|---|
| 三态 | 加载骨架屏 / 空数据一句人话 + 操作入口 / 出错显示错误码 + 重试 |
| 分层 | 页面里无 axios、无接口 URL、无字段名转换、无魔法状态值 |
| 权限 | 无权限路由被守卫拦下；菜单按角色隐藏 |
| 操作反馈 | 成功 toast、失败 toast 用后端 `msg`、危险操作二次确认 |
| 分页 | 页码 / 每页条数 / 总数正确；末页删空回退 |
| 体积 | `npm run build` 产物 ≤ 2 MB（当前 0.74 MB） |
| 刷新 | 任一页面刷新后不回登录页、不白屏 |

## 四、答辩演示动线（3 分钟）

1. **登录**（`admin / admin1234`）→ 侧栏出现 6 个菜单，右上角显示姓名
2. **工作台** → 4 张指标卡（说明数据口径：仅统计已完成订单）
3. **员工管理** → 搜索“张” → 新增一个员工 → 停用其中一行（开关变灰并 toast）→ 删除一条（二次确认）
4. **菜品管理**（待实现）→ 搜“宫保”→ 上下架切换
5. **订单管理**（待实现）→ 待接单 → 接单 → 派送 → 完成，打开详情看状态时间轴
6. 切到 **H5**（待实现）→ 点两个菜 → 下单
7. 讲一句工程话术：「接口层做了双数据源，演示版走内置数据；后端就绪后只改一个环境变量就能切真接口」
